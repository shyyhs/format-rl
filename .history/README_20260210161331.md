## Overview

FormatRL addresses the challenge of translating structured documents (XML/HTML) where preserving document structure is as important as translation quality. Traditional approaches either operate at the sentence level or rely on detag-and-project pipelines that suffer from error propagation. FormatRL employs **Group Relative Policy Optimization (GRPO)** on top of a supervised fine-tuning model to directly optimize novel structure-aware rewards.

**Key contributions:**

- **FormatRL**, a two-stage framework (SFT → GRPO) for structured document translation
- **TreeSim**, a reward measuring structural similarity between predicted and reference XML trees via tree edit distance
- **Node-chrF**, a reward measuring translation quality at the XML node level
- Additional reward functions including Tag-F1, XML-Match, BLEU, and XML-BLEU
- Application of **StrucAUC**, a fine-grained metric distinguishing minor errors from major structural failures

## Data Format

Training and development data should be in JSONL format, with each line containing a source–target pair:

```jsonl
["<div><p>源文本</p></div>", "<div><p>Target text</p></div>"]
```

or equivalently:

```jsonl
{"source": "<div><p>源文本</p></div>", "target": "<div><p>Target text</p></div>"}
```

The source should be a structured document with XML/HTML markup, and the target should be the translation preserving the same markup structure.

## Training

### GRPO Fine-tuning

Run GRPO training with DeepSpeed:

```bash
deepspeed --num_gpus=4 grpo_train.py \
    --train_file data/train.jsonl \
    --dev_file data/dev.jsonl \
    --model_path meta-llama/Llama-3.1-8B-Instruct \
    --output_dir checkpoints/formatrl \
    --ds_config config/ds_grpo.json \
    --rewards ted tag_f1 bleu \
    --epochs 10 \
    --lr 5e-6 \
    --per_device_batch 4 \
    --grad_accum 1 \
    --num_generations 2 \
    --max_prompt_len 1200 \
    --max_completion_len 1200 \
    --temperature 1.0 \
    --bf16 \
    --lang zh \
    --eval_steps 10 \
    --early_stop 10
```

### Available Reward Functions

| Reward | Description | Range |
|--------|-------------|-------|
| `ted` | **TreeSim** — Tree edit distance similarity between predicted and reference XML trees | 0–10 |
| `tag_f1` | Tag-level F1 score measuring markup tag overlap | 0–10 |
| `xml_valid` | Binary reward for XML well-formedness | {0, 10} |
| `xml_match` | Binary reward for exact XML structure match | {0, 10} |
| `bleu` | Sentence-level BLEU on tag-stripped text | 0–10 |
| `xml_bleu` | BLEU computed on matched XML segments (penalizes structural errors) | 0–10 |

Multiple rewards can be combined:

```bash
--rewards ted tag_f1 bleu
```

### Key Hyperparameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `--rewards` | `ted` | Reward function(s) to use |
| `--num_generations` | 2 | Number of completions per prompt for GRPO |
| `--temperature` | 1.0 | Sampling temperature for generation |
| `--top_p` | 1.0 | Nucleus sampling threshold |
| `--max_prompt_len` | 1200 | Maximum prompt token length |
| `--max_completion_len` | 1200 | Maximum completion token length |
| `--early_stop` | 10 | Early stopping patience (evaluation steps) |
| `--lang` | `zh` | Target language for BLEU tokenization (`zh`, `ja`, `ko`, etc.) |

## Reward Design

### TreeSim (Tree Edit Distance Similarity)

TreeSim computes the similarity between predicted and reference XML trees using the Zhang-Shasha tree edit distance algorithm. The similarity score is normalized to [0, 1]:

$$\text{TreeSim}(T_p, T_r) = 1 - \frac{\text{TED}(T_p, T_r)}{\max(|T_p|, |T_r|)}$$

where $|T|$ denotes the number of nodes in tree $T$.

### XML-BLEU

XML-BLEU extends standard BLEU by first checking structural alignment. If the predicted XML tree matches the reference structure, text segments are paired by position for BLEU computation. If structures don't match, the prediction is penalized with empty strings.

## Evaluation

We evaluate on the [SAP software-documentation benchmark](https://github.com/nicktien007/SAP-software-documentation-data) across four translation directions: De→En, En→De, Zh→En, En→Zh.

### Metrics

- **XML-Match**: Exact structure match rate
- **XML-BLEU**: Structure-aware BLEU score
- **StrucAUC**: Fine-grained metric distinguishing minor vs. major structural failures
- **TreeSim**: Tree edit distance similarity
- **Tag-F1**: Tag-level F1 score
- **BLEU**: Standard BLEU on tag-stripped text

## Results

FormatRL with TreeSim reward consistently outperforms both prompting and SFT baselines across nearly all evaluation metrics and four language pairs. Please see the paper for detailed results.
